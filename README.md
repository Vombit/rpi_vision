# rpi-vision

Система обнаружения застрявшего пластика в металлической детали. Разработка ведётся на Windows
(USB-камера через OpenCV), целевая платформа — Raspberry Pi (CSI-камера через Picamera2).

## Как это работает

Камер столько, сколько задано `config.CAMERA_COUNT` (1 или 2). Всё, что ниже,
у каждой камеры своё: поток захвата, хендл камеры, эталон, область интереса,
кнопки и статусы. Общие только порог тревоги (слайдер), кнопка **Refresh**
и входы GPIO.

```mermaid
flowchart TB
    CAM[Камера 1 / 2] --> CT[CaptureThread<br>capture.py, свой Camera на поток]
    CT -- frame_captured --> P[Processor<br>processing.py, QThread]
    P -- result_ready --> PANEL[CameraPanel<br>camera_panel.py]
    P --> PRE[preprocessing.py]
    P --> DET[detector.py]
    P --> REF[reference.py]
    PANEL --> GUI[MainWindow<br>main.py]
```

```mermaid
flowchart TB
    F[Полный кадр] --> R[Поиск совпадающих участков эталона]
    R --> V{Совмещение и видимость достаточны?}
    V -- нет --> U[Кадр не проверен]
    V -- да --> N[Локальная поправка яркости]
    N --> D[Разница внутри проверяемой зоны]
    D --> Q{Изменение повторяется в одном месте?}
    Q -- да --> A[Дефект и рамка]
    Q -- Разница ниже порога --> OK[Норма]
    Q -- Ожидается подтверждение --> U
```

- Нажмите **Set reference** на чистой детали. Программа совмещает пригодные кадры
  и записывает их медиану. Проверка идёт непрерывно.
- Для проверки только отверстия выделите область в превью, затем запишите эталон.
  Превью показывает выбранную область, а обработка получает полный кадр для поиска
  смещения. **Reset zone** возвращает полный кадр. После смены зоны запишите эталон снова.
- При проверке всего кадра неподвижный фон и движущаяся деталь совмещаются отдельно,
  когда их переносы можно определить по контурам.
- Если ориентиры по кадру согласуются с небольшим изменением масштаба или поворотом,
  программа компенсирует их до сравнения. После такого совмещения разница вдоль
  кромки в пределах двух рабочих пикселей подавляется.
- При сильных бликах детектор также проверяет, сохранилась ли текстура металла
  под изменением яркости. Пересвеченные участки содержат меньше информации о
  мелком пластике, поэтому чувствительность проверяют на реальном образце.
- Сигнал GPIO `detect` запускает отдельную проверку по следующим кадрам.
- При смазе, сильном пересвете или потере зоны программа показывает «Кадр не
  проверен», если видимой части недостаточно для уверенного результата.
  Под статусом указана причина. Процент потери деталей при экспозиции считается
  по пикселям, которые были различимы в эталоне и стали белыми или чёрными в кадре.
  «Проверка дефекта…» означает, что изменение ждёт подтверждения следующим кадром.

Если пересвет затрагивает металл вокруг отверстия, выделите проверяемую область.
Если внутри отверстия теряются детали, уменьшите выдержку и усиление на камере и
проверьте видимость на всех шагах. Рассеянная подсветка помогает уменьшить прямые
блики. После изменения освещения или настроек камеры заново запишите эталон.
- **Settings...** у каждой панели — правка параметров камеры (см. ниже).
- Все параметры алгоритма — в `config.py`.

## Параметры камеры на Windows

- Кнопка **Settings...** открывает настройки подключённой камеры OpenCV.
  Для Windows приложение сначала пробует DirectShow, затем Media Foundation.
- **Apply** применяет только изменённые значения. Ручная выдержка, усиление,
  фокус и другие параметры зависят от драйвера и показаны в его единицах.
  Диалог показывает значения после записи и сообщает об отказах драйвера
  или отсутствии подтверждения чтением. После применения запишите эталон снова.
- Принятые значения сохраняются в `opencv_camera_settings.json` для индекса
  камеры и её бэкенда. Они восстанавливаются при открытии камеры.
- Этот же диалог используется для других камер OpenCV, если интерфейс V4L2
  недоступен. Набор работающих параметров определяется бэкендом.

## Параметры камеры (V4L2)

Те же команды, что и руками в консоли, только при каждом открытии камеры:

```
v4l2-ctl -d /dev/video0 -c auto_exposure=1 -c exposure_absolute=300
```

- Всё перечисляемое в `config.V4L2_CONTROLS`: ключ — индекс камеры, значение —
  `{контрол: значение}`. Порядок важен: авторежимы (`auto_exposure`,
  `white_balance_temperature_auto`) ставятся первыми, иначе камера вернёт
  авторежим и затрёт ручные экспозицию/баланс белого.
- Прописывается при открытии камеры (бэкенд `opencv`). Для этой камеры
  `LOCK_CAMERA_PARAMS` не применяется: он включает автоэкспозицию через OpenCV
  и затёр бы V4L2-значения.
- Контрола, которого нет на камере, пропускается с предупреждением в лог.
- Требуется пакет `v4l-utils` (`sudo apt install v4l-utils`), в нём `v4l2-ctl`.
  Без него программа работает как раньше, кнопка **Settings...** объясняет, чего не хватает.
- Кнопка **Settings...** показывает реальные контролы камеры с их диапазонами и
  текущими значениями (меню — выпадающим списком, read-only/неактивные —
  заблокированы). Кнопка **Apply** применяет значения к камере, пишет их в
  `config.V4L2_CONTROLS` и в `camera_settings.json`; файл перекрывает конфиг при
  следующем запуске. Удалил `camera_settings.json` — снова действуют значения
  из `config.py`.

## Запуск (Windows / dev)

Требуется Python 3.14 и [uv](https://docs.astral.sh/uv/):

```
uv sync
uv run main.py
```

Камера выбирается в выпадающем списке над каждым полем превью, общий список
обновляется кнопкой **Refresh**. Лог — `app.log` (очищается при каждом запуске).

## Несколько камер

`config.CAMERA_COUNT = 1` (по умолчанию) или `2` — столько полей превью будет
в окне. У каждого поля своя камера, свой эталон, своя область интереса и свои
кнопки.

- При старте панели разбирают доступные камеры по порядку (первая — камера 0,
  вторая — камера 1), дальше индекс выбирается вручную в выпадающем списке над
  полем. Если камер меньше, чем панелей, лишняя панель показывает
  «Camera not available» и оживает по кнопке **Refresh**, когда камера появится.
- Ширина поля: `PREVIEW_WIDTH` делится между панелями, но не уже `MIN_PANEL_WIDTH`
  (380 px) — иначе три кнопки в ряд не поместятся. Окно шире `PREVIEW_WIDTH + 150`.
- Порог тревоги (слайдер) общий для всех камер; `change_ratio` у каждой считается
  от площади её области.

## Запуск на Raspberry Pi

```
sudo apt install python3-picamera2 python3-opencv python3-pyside6.qtwidgets
uv venv --system-site-packages   # чтобы venv видел apt-пакеты
uv sync
uv run main.py
```

- `picamera2` и `opencv` ставим через apt: pip-сборки на ARM тяжёлые и конфликтуют с libcamera.
- В `config.py`: `CAMERA_BACKEND = "picamera2"` (или оставить `auto`) и `LOCK_CAMERA_PARAMS = True` — фиксация экспозиции/баланса белого (на Windows выключена: роняет FPS).
- На станке проверьте чистую деталь и пластик на каждом из шести шагов. Подберите
  `REGISTRATION_MAX_SHIFT` по ходу в пикселях рабочего кадра (`IMAGE_WIDTH` ×
  `IMAGE_HEIGHT`). Проверьте, что два пригодных кадра успевают обработаться
  до следующего перемещения.
- Для настройки `PIXEL_THRESHOLD` / `MIN_AREA` включите `DEBUG = True`.
  В `debug/` появятся маска дефекта, маска проверяемых пикселей и разница после
  совмещения. Синтетические проверки запускаются через `python -m unittest discover -s tests`.

## Автозапуск при загрузке системы

`config.AUTORUN = True` — при старте программа пишет systemd-юнит
`/etc/systemd/system/rpi-vision.service` и делает `systemctl enable`, так что
после перезагрузки приложение поднимается само.

```
sudo -E uv run main.py     # первый запуск с правами root (нужны sudo -n при записи юнита)
```

- Юнит описывает текущий запуск (тот же интерпретатор и каталог), поэтому после
  переезда или пересоздания venv достаточно перезапустить программу — юнит
  перепишется сам.
- Нужен `DISPLAY`: берётся из окружения, иначе `config.AUTORUN_DISPLAY`
  (на Raspberry Pi OS это X11, `:0`). Без него Qt не подключится к дисплею.
- Снять автозапуск: `uv run python -c "import autorun; autorun.disable()"`.
- Логи запуска из-под systemd — `journalctl -u rpi-vision`.
